    Policies¶

    This page shows how to run your model in Hylo and which agent to wrap it in.

    A policy is a model or controller used by an agent. This guide covers configuring policy agents; the agent overview also covers programs and typed tool calls.

    Run¶

    Complete Installation. From bench/, run the shipped CPU controller:

    uv run hylo run examples/configs/mujoco_reach.yaml

    The command prints episode outcomes and a run directory. The quickstart explains the expected result. To use your own compatible policy, replace the agent block as shown below; artifact:policy.bc and artifact:policy.flow refer to artifacts you must first build or register.

    Policy and agent¶

    A policy returns action chunks from an observation. An agent holds a policy and decides how to use its chunks (concepts). Each wrapper requires a compatible policy contract.

    See Agents for the control modes and their relationship to programs and tool calls.

    The optional simplememvla agent combines an episode video-history buffer with a compatible frozen video-conditioned checkpoint. It uses the released Panda controller interface and an explicit shared-batch runtime. Configuration, model requirements and verification limits are in Video memory.

    Agent types¶

    Agent Runs the policy Key params
    policy chunk by chunk, with seeded noise policy, execution_steps, seed_noise, noise_scale
    temporal_ensemble every step, exponentially weighted over overlapping chunks (as in ACT) policy, m (weight decay; 0 = plain average)
    steered draws n_samples seeded chunks per decision and executes one, with optional recovery rules sampler, steering 
    agent:
  type: policy
  params:
    policy: {type: policy.bc, params: {path: "artifact:policy.bc"}}
    execution_steps: 8

    agent:
  type: temporal_ensemble
  params:
    policy: {type: policy.bc, params: {path: "artifact:policy.bc"}}
    m: 0.01

    agent:
  type: steered
  params:
    sampler: {type: policy.flow, params: {path: "artifact:policy.flow"}}
    steering: {n_samples: 4, selector: medoid}

    sampler takes a policy spec, like policy in the other two agents.

    A policy returns chunks of T actions. policy and steered execute the first execution_steps of each chunk (default: the policy's default_execution_steps(), capped at T). temporal_ensemble asks at every step.

    Use policy to run a policy chunk by chunk. The other two fit these cases:

    • temporal_ensemble gives smoother motion from a deterministic chunk policy, at the price of one policy call per step. It returns one action per call, so it works only with sync timing (experiments).
    • steered suits stochastic policies (flow matching, diffusion), when you can afford n_samples calls per decision. Everything in steering is data, so a campaign can propose and gate changes to it.

    steering keys:

    Key Default Meaning
    n_samples 1 chunks drawn per decision (1 to 8; cost grows linearly on CPU)
    selector first first, medoid, or gripper_vote_medoid (keep the chunks that agree with the gripper majority, then take their medoid)
    noise_scale 1.0 scale of the initial noise
    execution_steps the policy's actions executed from each chunk
    seed_noise true derive the noise from seeds (see below)
    rules [] up to 4 recovery rules

    A rule watches one feature and fires an action when the feature crosses a threshold:

    steering:
  n_samples: 4
  selector: gripper_vote_medoid
  rules:
    - {name: unstick, feature: still_steps, op: ">=", value: 20, action: resample, params: {noise_scale: 1.5}}
    - {name: regrasp, feature: grasp_attempts, value: 3, action: backoff, params: {steps: 8, dz: 0.5}, max_fires: 1}
    • Features: still_steps, grasp_attempts, disagreement (spread between samples), steps. eef_key and gripper_key rename the state keys the first two read (default eef_pos, gripper_qpos).
    • Actions: resample (with params.noise_scale) and backoff (up along action dimension 2 and open the gripper; end-effector delta control only, such as LIBERO).
    • cooldown (default 30 steps) and max_fires (default 3 per episode) limit firing.

    Policy contract¶

    A policy is a policies plugin with four methods:

    class ChunkPolicy(Protocol):
    def spec(self) -> AgentSpec: ...
    def reset(self, ctx: EpisodeContext) -> None: ...
    def default_execution_steps(self) -> int: ...
    def sample(self, observation: Observation, seeds: list[int] | None, noise_scale: float) -> np.ndarray:
        """(N, T, A) action chunks in the environment's units, one per seed."""

    Deterministic policies (regression, retrieval, scripted) ignore the seeds. Stochastic ones (diffusion, flow matching, sampled tokens) must take their randomness from the seeds only. Agents compute the seeds from the task, the chunk index and the sample index. So two agents compared on the same init state draw the same noise, which keeps paired comparisons fair.

    uv run hylo plugin new policy NAME      # scaffold a policy package
uv run hylo plugin check policy NAME    # conformance: shape, finiteness, seed determinism

    The adding a policy tutorial walks through one, and extending lists what the check covers.

    Reference policies¶

    hylo-policies ships one small, weights-free implementation of each common policy family, in numpy only. You train them from your own runs and they are sealed as artifacts. They are not the published architectures at scale.

    Plugin Family Idea (reference) Stochastic
    policy.knn retrieval nearest neighbours in observation space, averaged chunks (VINN) no
    policy.bc regression BC MLP from observation to an action chunk, MSE (BC with chunking) no
    policy.flow flow matching velocity field from noise to the chunk, Euler integration (pi0, SmolVLA action experts) yes
    policy.tokens tokenized actions each dimension binned, categorical heads, sampled (RT-1, OpenVLA-style) yes
    policy.mpc model-based planning cross-entropy method over action sequences in a learned world model (MPC) yes

    Learners of the same names build policy_params artifacts from successful episodes. world_model.state builds the world model that policy.mpc plans in (learning).

    Train and evaluate¶

    cd bench
uv run python examples/policies/compare.py    # data -> every learner -> mujoco-reach scorecards -> leaderboard (~3 min)

    cd bench
uv run hylo run examples/configs/mujoco_reach.yaml --split search --output runs/policies/demos \
    --set benchmark.params.protocol=rsi                    # demonstrations, from a development split
uv run hylo learn examples/policies/jobs/flow.json           # a sealed policy_params artifact
uv run hylo store ls --kind artifact                         # its id: artifact:policy.flow@<digest>
uv run hylo run examples/configs/mujoco_policy_flow_steered.yaml
uv run hylo bench run mujoco-reach --name flow-steered \
    --policy examples/configs/mujoco_policy_flow_steered.yaml

    The example uses the name-only id artifact:policy.flow. Pin its digest before comparing runs.

    Compare two scorecards with hylo bench compare A.json B.json (an exact paired McNemar test) before reading a difference into them. The results of compare.py are on the leaderboard.

    Model adapters¶

    The hylo-policy-lerobot adapter runs LeRobot policies on CPU, in the lerobot runtime that bench's LIBERO setup installs. It registers lerobot twice:

    • as a policy, for Hylo's agents (policy: {type: lerobot, ...}), with noise from Hylo's seeds;
    • as an agent (type: lerobot), which runs chunk by chunk, LeRobot's way, with unseeded noise.

    The factories below wrap the policy in an agent for you:

    Agent What it adds
    lerobot the policy, chunk by chunk
    lerobot.steered the steered agent: seeded noise, sample-and-select, recovery rules
    lerobot.critic_steered samples n_samples chunks and executes the one a learned chunk critic values most
    lerobot.memory_steered starts flow sampling from an action retrieved from its own successes (action memory)
    lerobot.noise_steered biases the initial noise towards noise that produced similar successful chunks 
    agent:
  type: remote
  params:
    ref: lerobot.steered
    runtime: lerobot
    params: {repo_id: lerobot/smolvla_libero, num_threads: 4, steering: {n_samples: 1, seed_noise: true}}

    openpi (hylo-policy-openpi) is an agent that calls an openpi policy server over WebSocket. Its params are url (default ws://127.0.0.1:8000) and an input preset (default libero). The plugin catalogue says how far it is verified.

    SmolVLA (lerobot/smolvla_libero) on a LIBERO-10 task, every 10th camera frame of one episode.

    Weight licences differ per checkpoint: PaliGemma-based pi0 and pi0.5 checkpoints are under the Gemma Terms of Use. The plugin catalogue lists each plugin's maturity and licences.

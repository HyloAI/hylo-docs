    Core examples¶

    Source

    Reproduction record from hylo-harness: examples/core/README.md. Every number on this page was measured by the scripts next to it; run them to reproduce.

    Six small scripts, one per capability of hylo-core: the kernel, the SafetyShield, traces and replay, remote components and the wire codecs, conformance with sealed artifacts and the store, and the kernel's timing modes with the operator channel. Each script runs real episodes, measures something, prints a short results table and writes result.json.

    The environments are the MuJoCo tasks of hylo-bench (mujoco.planar_reach, mujoco.table_reach, from hylo-env-mujoco). The scripts refer to them only by their registry name, so they need that package installed in the venv. The development workspace installs it.

    Running¶

    From the harness repository root:

    uv run python examples/core/01_first_episode.py            # full run
uv run python examples/core/01_first_episode.py --quick    # under 60 s (here: 2-3 s)
uv run python examples/core/01_first_episode.py --out /tmp/x
uv run pytest tests/test_examples_core.py                  # every example with --quick

    Output goes to runs/examples/core/<slug>/ (gitignored): result.json, any figure, and the run directories with their traces. Seeds are fixed, so the numbers below reproduce, except wall-clock timings.

    Findings¶

    • A WebSocket placement changes the config digest. ExperimentConfig.measured() drops env.remote and a remote agent's runtime, so a stdio env has the same digest as in-process (05c573fe1309dd6d). A WebSocket env is {type: remote.ws, params: {url}} instead, so the digest changes, and it includes the URL: with --port 0 it is different on every run. A stdio agent (type: remote) also gets its own digest. Results do not depend on placement (example 04), so comparing runs by digest across placements does not work today.
    • Guard order matters. Guards run in the order they are listed, and the max_delta shorthand is always inserted first. With max_delta plus a norm_limit guard, the norm scaling runs after the rate limit and produces step-to-step jumps of up to 0.28, above the 0.25 limit. Listing norm_limit and then delta_limit as guard plugins keeps the jumps at 0.25 (example 02, both orders measured).
    • The unsafe stream does not lower success here. On planar reach the noisy agent succeeds in every config. What the shield changes is the motion: smaller steps, lower peak speed, lower peak acceleration. Interventions count every modified step, so a stricter config shows more interventions.
    • Realtime fails well before the latency reaches the chunk horizon. With 10-step chunks, success drops to 0 at a 7-step latency, not at 10. The aligned merge drops the first t - s actions of a chunk, which assumes the robot followed the previous plan in the meantime. While the queue is empty the robot holds instead, and the rest of a P-controller rollout is small, so the arm only crawls. The watchdog catches the case where nothing is left to execute (latency of 10 steps or more).
    • The stdio env proxy has no snapshot/restore. RemoteEnvironment does not forward snapshot/restore, so that conformance check is skipped over stdio. In-process, MuJoCo passes it.
    • Reusing an episode id appends to its trace file. TraceStore opens episode files in append mode. The scripts that use fixed episode ids clear their trace directory first.

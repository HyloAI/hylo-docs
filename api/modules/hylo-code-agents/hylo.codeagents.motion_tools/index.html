    hylo.codeagents.motion_tools¶

    Package: hylo-code-agents · Core contracts

    motion_tools ¶

    The motion studio's tool layer (RFC-0006 part 8), shared by the guided studio (motion.py) and free mode (motion_free.py): the model-facing tools, the backend that runs them, and the final report of a run.

    • RobotMotion: a motion retargeted to one character (robot qpos, or a rigged character's posed keypoints).
    • ToolBackend: the real tools, each in its own environment: hylo-tools workers (text_motion kept loaded, human, render and the perception tools), the MuJoCo worker (motion_sim: retarget, check, validate) and the media worker (motion_media: clip, compose, rig). Tests pass a fake with the same methods.
    • StudioTools: what the model calls: text_motion, video_motion, pose_from_image, retarget (any character of motion_characters), check, render (robots through the hylo-tools render tool, rigged characters through Blender), lineup (the same motion on several characters, one labelled video grid), look (frames of a video for the model), finish. Every call is logged and timed; slow calls pause the sandbox's block clock.
    • finalize: the final motion -> motion.npz, check.json, a report per character (characters.json) and the videos.

    Reference video -> human motion (the human tool: MediaPipe Pose 3D keypoints; approximate world grounding, static camera). start / seconds select a window.

    Your own motion: joints (T, 17, 3) in NAMES order, metres, z up.

    retarget ¶

    retarget(motion: Any, robot: str | None = None) -> RobotMotion

    Skeleton motion -> character motion: robots by keypoint IK (MuJoCo), rigged characters by bone driving (Blender); see motion_characters for the characters.

    report ¶

    report(motion: Any, robot: str | None = None, physics: bool = True) -> dict[str, Any]

    The full plausibility report (check.json): retargeting, kinematic metrics, physics rollouts (robots with actuators); for a rigged character its retargeting and contact metrics from Blender.

    check ¶

    check(motion: Any, robot: str | None = None, physics: bool = False) -> dict[str, Any]

    Plausibility of the robot motion for the model: a list of real problems (floor penetration, sliding feet, self-collision, joint-limit violations, poor retargeting) and the kinematic metrics. The physics rollout (physics=True) is information only; the final report always has it. With a local model it is off by default: shown the falls, the model kept trading the request away for a motion that stays up.

    render ¶

    render(motion: Any, camera: str = 'track', style: str | None = None, robot: str | None = None, physics: bool = False) -> str

    Render to MP4 (style "blender": Cycles, slower, nicer; "mujoco": fast; "auto"); camera "track", "orbit" or "fixed". physics=True renders the physics rollout of the last check instead. Returns the path; a still frame is attached to your next feedback. Rigged characters render in Blender (track camera).

    lineup ¶

    lineup(motion: Any, characters: list[str] | None = None, cols: int | None = None) -> str

    The same motion on several characters: one render per character (each with its own proportions and the same camera angle), composed into one labelled video grid. Characters default to the run's list (or all). Returns the MP4 path; a still of each render is shown.

    look ¶

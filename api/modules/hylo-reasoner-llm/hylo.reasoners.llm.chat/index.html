    hylo.reasoners.llm.chat¶

    Package: hylo-reasoner-llm · Core contracts

    chat ¶

    Chat models for tool-using agents (RFC-0006 part 7): one interface, images, per-call accounting.

    model = build_chat({"backend": "ollama", "model": "qwen3.5:35b-a3b", "vision": True})
reply = model.chat([{"role": "system", "content": "..."},
                    {"role": "user", "content": "...", "images": [rgb_array]}])
reply.text, reply.tokens_in, reply.tokens_out, reply.latency_s, reply.cost_usd

    Backends (the backend key of a spec): openai any OpenAI-compatible /chat/completions endpoint (vLLM, DeepSeek, OpenRouter, ...); the key is read from the environment variable named by api_key_env; price gives USD per million tokens ollama the same against a local Ollama server (http://localhost:11434/v1), price 0 anthropic the Anthropic Messages API (key from ANTHROPIC_API_KEY unless api_key_env says otherwise) claude_code the Claude Code CLI as a subprocess (claude -p --output-format json, prompt on stdin) codex the Codex CLI as a subprocess (codex exec ... -, prompt on stdin) scripted a deterministic fake for tests: canned replies, or a function of the conversation

    Messages are dicts {"role": "system" | "user" | "assistant", "content": str, "images": [...]}; an image is an (H, W, 3) uint8 array or PNG bytes, sent only to models with vision. Keys never appear in configs or traces. Standard library only (and Pillow for PNG encoding).

    Native tool calls (RFC-0007): chat(messages, tools=[ToolSpec | {"name", "description", "parameters"}]). The reply's tool_calls are ToolCall(id, name, arguments); a call whose arguments are not a JSON object keeps them in raw with error set, so the agent can answer it instead of crashing. The conversation stays in one neutral shape and each backend translates it at the wire:

    {"role": "assistant", "content": "...", "tool_calls": [{"id", "name", "arguments"}], "reasoning": "..."}
{"role": "tool", "tool_call_id": "...", "name": "...", "content": "<result text>", "images": [...]}

    OpenAI-compatible endpoints get tools as functions (images of tool results follow in a user message, since tool messages carry text only there); replay_reasoning sends an assistant turn's reasoning back as reasoning_content (needed by endpoints that continue a reasoning chain across tool calls). Anthropic gets tool_use / tool_result blocks. Backends without tool support (the coding-agent CLIs) are wrapped by TextTools, which describes the tools in the system message and parses fenced tool blocks from the text.

    ScriptedChat ¶

    ScriptedChat(replies: Sequence[Any] | Callable[[list[Message]], Any] = (), *, then: Any = None, model: str = 'scripted', vision: bool = True, price: Mapping[str, float] | Price | None = None)

    Replies from a list (in order) or from fn(messages) -> reply. A reply is a string (text), or a dict {"text": ..., "tool_calls": [{"name", "arguments"} ...]} to script native tool calls. Token counts are len(text) // 4, so tests can exercise budgets; calls keeps every conversation it was shown and tools the tool lists it was offered.

    TextTools ¶

    TextTools(model: ChatModel)

    Gives a model without native tool calls the same interface: the tools are listed in the system message, the model writes each call as a fenced block

    ```tool
{"name": "observe", "arguments": {...}}
```

    and tool results come back as user messages. The wrapped model's accounting is passed through.

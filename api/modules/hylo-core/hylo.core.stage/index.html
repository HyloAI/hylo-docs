    hylo.core.stage¶

    Package: hylo-core · Core contracts

    stage ¶

    Stage contract (hylo.stage/v0.1): an open world as an entity tree that a person, a model or a program edits through patches, with every revision kept. A world engine (bench: hylo.envs.mujoco.world) compiles a stage into a running simulation; tools (hylo-agents hylo.agents.worldtools) read and change it.

    It differs from the table-top hylo.scene/v0.1 on purpose: a scene is one manipulation task written as data (objects on a table and a success predicate); a stage is a general workspace (robots of any kind from packs, mounted on each other or on fixtures, meshes, cameras, people) that changes while someone works in it.

    Frames and units: metres, radians in quaternions; world frame +z up; quat is (w, x, y, z) like MuJoCo.

      entity      id, parent (an entity id or none: the world), label, pose in the parent's frame, locked
              and components, each optional:
    shape     a primitive (box, sphere, cylinder, capsule, plane): size, rgba
    mesh      a mesh file (obj, stl) with a scale; its collision geometry comes from `collision`
    body      physics: dynamic (has a free joint) or static, mass or density, friction
    collision how the visual geometry becomes contact geometry: the primitive itself, the convex hull, convex
              parts (a decomposition file) or voxel boxes (hylo-tools `physicalize` writes them)
    robot     a robot from a pack (hylo.pack/v0.1): pack name, base fixed or free, `mount` onto a body of
              another entity, initial joint values
    camera    a camera: vertical field of view, image size, depth on/off; `body` names the body it rides on
    light     a directional or spot light
    human     a walking person (hylo.envs.mujoco.humans): route, speed, appearance

    A patch is a list of operations with the revision it was written against (compare and swap): add an entity, remove one (with its children when cascade), update some of its fields, reparent it. The store applies a patch to a copy, refuses it if the stage changed in between or an operation touches a locked entity, validates the result and writes it as the next revision; old revisions are never changed, and restore(n) commits revision n again as the newest.

    StageStore ¶

    StageStore(root: str | Path)

    Stages on disk: <root>/<name>/current.json, every revision in history/rev-<n>.json and one line per commit in log.jsonl. Commits hold an exclusive lock, so several processes may write the same stage.

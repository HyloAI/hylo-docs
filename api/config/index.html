    Configuration¶

    What an experiment measures, where its components run on one machine, and how plugins are found. For the YAML side, see the experiment config schema and execution profiles; for how plugins are found, see the plugin system.

    Execution profiles¶

    profile ¶

    Execution profiles (hylo.profile/v0.1): where components run on this machine, kept out of experiment configs.

    An experiment says what is measured. Where an interpreter lives, which rendering library to load, where the model cache is, differ per machine and must not change an experiment's identity. Configs name a runtime instead:

    env:   {type: libero, remote: {runtime: libero}}
agent: {type: remote, params: {ref: lerobot.steered, runtime: libero, params: {...}}}

    and each machine's profile says what that runtime is:

    schema_version: hylo.profile/v0.1
runtimes:
  libero:
    python: /home/me/hylo/bench/envs/libero/.venv/bin/python
    env: {MUJOCO_GL: osmesa, LIBERO_CONFIG_PATH: /home/me/hylo/bench/envs/libero/config, HF_HOME: ...}

    The profile is found at $HYLO_PROFILE, else ~/.config/hylo/profile.yaml. hylo profile shows and edits it; bench's envs/libero/setup.sh registers the runtime it builds. Explicit python / env in a config still work and take precedence over the runtime's (for a one-off); neither enters the experiment digest. The profile also says where this machine's run and artifact store is (store:, set by hylo store init PATH).

    PROFILE_SCHEMA module-attribute ¶

    PROFILE_SCHEMA = 'hylo.profile/v0.1'

    Plugin metadata¶

    plugins ¶

    Contract versions and plugin metadata (RFC-0005 part 4).

    Every plugin group is a contract with a version (hylo.policy/v0.1, hylo.agent/v0.1, ...). A distribution declares which version of each contract its plugins implement, and what is known about them, in one dictionary exposed under the hylo.meta entry-point group (a module with no heavy imports, so listing plugins never loads them):

    [project.entry-points."hylo.meta"]
hylo-policy-lerobot = "hylo.policies.lerobot:META"

META = {
    "contracts": {"agents": "hylo.agent/v0.1", "policies": "hylo.policy/v0.1"},
    "maturity": "implemented",                                  # the default for this distribution's plugins
    "plugins": {"agents/lerobot.steered": {"weights": "per checkpoint: ..."},
                "datasources/lerobot.dataset": {"maturity": "unverified", "notes": "..."}},
}

    The code licence is the distribution's own (license in its pyproject); weights names the licence of model weights a plugin downloads or needs, which is often different. Maturity:

    implemented     run end to end on its intended target (a real simulator or robot), with recorded runs
unverified      tests pass, but never run end to end on its intended target here
needs-hardware  needs hardware this lab has not connected yet
test-double     for tests and conformance only (`testing.*` names)

    The registry refuses to load a plugin whose declared contract is incompatible with this core: another major version, or a newer minor version (a plugin written against features this core does not have). A plugin without a declaration still loads; hylo plugins shows it as undeclared and hylo plugin check warns.

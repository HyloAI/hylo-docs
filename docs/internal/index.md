# Internal documentation

Start with the current implementation and decisions, then follow the supporting research and dated records.
For product use, start with [Get started](../getting-started/installation.md).

| Question | Start here |
|---|---|
| What does the system implement? | [Architecture](../design/overview.md), [repository structure](../design/repository-structure.md) |
| What direction and work remain? | [Roadmap](../design/roadmap.md); its dated sections describe their recorded state |
| Which decisions were adopted? | [RFC status index](../rfcs/index.md), including partial, proposed and withdrawn work |
| What do we currently conclude from research? | [Research conclusions](../research/index.md#current-conclusions) |
| What evidence supports a result? | [Experiment records](../research/index.md#experiment-records) |
| What was the original plan? | [Historical summary](../EXECUTIVE-SUMMARY.md), [architecture snapshot](../design/architecture.md), [MVP](../design/mvp-v0.1.md) |

Use RFCs for decisions and changes to contracts. Keep measurement conditions, negative results and reproduction
records with the experiment. Historical plans do not override the current interface documentation.

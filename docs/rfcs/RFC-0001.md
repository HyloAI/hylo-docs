## 1. Summary

Build a lightweight Harness in which **the Kernel owns the execution loop**, centered on **enforced typed contracts + a single safety checkpoint + an event-sourced Trace**; Simulators, Benchmarks, Policies, Reasoners, Memory and improvement algorithms all plug in through protocols and plugins. Reuse the vla-eval (benchmark containers) and openpi (policy server) ecosystems by being **protocol-compatible**, reuse inspect-robots (safety/compatibility) and RPent (tool layer) by **porting**, and reuse Zetta (RSI gate and candidate schema) by **borrowing the design and rewriting**. v0.1 delivers a minimal credible RSI loop on MuJoCo + one external benchmark.

## 2. Motivation

Research findings (`technology-gap-analysis.md`): existing projects are mature enough for "single VLA × single benchmark scoring", but none simultaneously satisfies:
1. All actions pass through one safety checkpoint that is on by default and cannot be bypassed (the inspect-robots programmatic API approves everything by default; RPent/Zetta give the LLM full permissions);
2. A replayable Trace that includes reasoning and memory evidence (inspect-robots logs cannot be replayed; agent-lightning deletes after reading);
3. An improvement loop with validation/held-out separation and rollback (Zetta is closest but lacks both);
4. A unified memory layer with spatial semantics;
5. A way of composing Agents that is not tied to a VLA or an LLM.

## 3. Decisions

### D1. The Kernel owns the loop; Served mode is also supported

- **Decision**: Driven mode by default (`EpisodeRunner`: reset → act → shield → step). Provide `wc-bridge-vlaeval` to wrap an Agent as a vla-eval ModelServer (Served mode).
- **Alternatives**: (a) Let the benchmark own the loop as vla-eval does—gives up step-level control, disturbance injection, privileged state isolation and shadow replay; (b) let the LLM SDK own the loop as RPent does—safety and timing become uncontrollable.
- **Cost**: The two modes produce Traces with different information content (Served mode has no per-step reward/privileged state), so Served mode results cannot be the sole evidence for RSI validation.

### D2. `Agent` is the only Kernel-level intelligence abstraction

- **Decision**: The Kernel only calls `Agent.reset/act/on_step/on_episode_end`. Reasoner/Planner/Policy/WorldModel/Memory are internal components of `ComposableAgent`.
- **Alternative**: The Kernel orchestrates Reasoner + Policy directly (dual loop written into the Kernel). Rejected because: it hard-codes one cognitive architecture into the core; end-to-end VLAs need no Reasoner.
- **Cost**: The Reasoner/Policy collaboration conventions (triggers, async submission) are defined by `wc-agents` rather than core, so third parties may implement different semantics—constrained through the observability of Decision events and conformance tests.

### D3. An in-house event-sourced Trace as primary storage

- **Decision**: `wc.trace/v0.1` = one JSONL event stream per episode + content-addressed blobs. LeRobotDataset v3, Rerun and inspect-robots EvalLog are **export targets**.
- **Alternatives**: (a) Use LeRobotDataset directly—designed for training, has no reasoning/memory/safety events; (b) OpenTelemetry spans—suited to service call chains, not to high-frequency arrays and replay; (c) inspect_ai logs—built around LLM messages, no per-step multimodal data; (d) MCAP—could be considered in v0.2 as a binary container replacing JSONL.
- **Cost**: One more format; JSONL + base64 is inefficient for images (>64 KB is already offloaded to blobs).

### D4. Do not use LangGraph/inspect_ai as the execution engine

- **Decision**: Both serve only as optional adapter packages (LangGraph → Reasoner; DSPy → offline candidate generator).
- **Rationale**: LangGraph superstep + checkpoint overhead does not match 5–50 Hz control, and it hard-depends on langchain-core; inspect_ai's Solver/TaskState is built around LLM message flow (inspect-robots' own choice to "mirror its semantics without depending on it" corroborates this).

### D5. RSI candidates are declarative by default; Protected Scope

- **Decision**: v0.1 candidate = dotted-path config patch; v0.2 extends to critic/recovery rules, prompts, skills and policy checkpoint references. Candidates must not touch `safety/benchmark/trace/scorers/evolution/env/schema_version`. Code candidates execute only in an isolated runtime.
- **Alternative**: Allow the LLM to generate and execute code directly (Voyager/ASPIRE style). Deferred until an isolated runtime is available (the same conclusion as Zetta).

### D6. Three-way split; held-out report-only; rollback is first-class

- **Decision**: train (diagnosis) / validation (selection) / heldout (report only); seeds must not cross splits; promotion requires parent == active; rollback writes to the ledger.
- **Rationale**: Fixes the overfitting risk in Zetta's default flow of "gating only on the training failure seeds", and the lack of rollback in all projects.

### D7. Single repository with multiple packages (**amended at review**)

- **Decision (amended)**: everything lives in the existing `dyna-harness` repository for now: a uv workspace with `packages/` (wc-core, wc-bench, wc-agents, wc-memory, wc-evolve, worldcurrent-cli), `adapters/` (wc-env-mujoco, later LIBERO etc.) and `physical-ai-research/` (now `docs/`; the prototype in it was removed on 2026-10-31) (this research workspace). Packages are split into their own repositories later, using the criteria in `repository-structure.md`.
- **Originally proposed**: a separate `worldcurrent` product monorepo + a `worldcurrent-research` repository.
- **Alternative A: polyrepo** (one repo each for core / bench / agents / memory / evolve / each adapter)—strongest independence, but during v0.1 contract changes would need cross-repo coordinated releases, which is too costly.
- **Alternative B: single package** (one `worldcurrent` containing everything, with extras separating dependencies)—simplest, but cannot enforce inter-layer dependency rules in CI, and third parties cannot install only core.
- **Rationale for the compromise**: separate packages provide replaceability, a single repo provides atomic changes; the conditions for splitting repos are written into `repository-structure.md`.

### D8. Protocol compatibility strategy

- Policy side: the simple backend is compatible with the **openpi WS wire protocol** (broadest ecosystem); the rich backend follows LeRobot's versioned envelope.
- Benchmark side: **vla-eval protocol** (Served mode).
- Env side: our own `wc.envserver` (the vla-eval protocol is benchmark-driven and unsuited to Kernel-driven per-step RPC).
- All protocols forbid pickle; array dtype whitelist.

### D9. Contract implementation: pydantic v2 models + Protocol (**amended at review**)

- **Decision (amended)**: every data contract that crosses a boundary (process, file, version, plugin) is a frozen pydantic v2 model with `extra="forbid"` (`worldcurrent.core.contract.Contract`). numpy arrays use the `NDArray` annotated type and free-form payloads use `JsonAny`; both round-trip through JSON via `core.codec`, so `model_dump(mode="json")` / `model_validate` is the entire wire format (the hand-written wire module of the prototype is gone). Runtime handles that hold callables (`EpisodeContext`, `ReasonerContext`, `SafetyContext`) stay plain dataclasses. Behavioural interfaces stay `typing.Protocol`.
- **Benefits**: typos fail loudly; discriminated unions (`InitSpec`); JSON Schema for every contract (`wc schema <name>`); one serialization path for trace, EnvServer and configs.
- **Measured cost**: Kernel overhead on the test-double environment rose from 27.9 µs/step (dataclasses) to 33.1 µs/step (pydantic), about +5 µs/step, which is negligible against a 20 ms step budget at 50 Hz. Core now depends on numpy, pydantic and pyyaml.
- **Originally proposed**: frozen dataclasses without pydantic.

## 4. Prototype Evidence

| Claim | Evidence |
|---|---|
| Contracts can carry both pure-Python environments and MuJoCo | the test double and MuJoCo share the Kernel/Scorer; MuJoCo 300 episodes 100% success |
| Out-of-process Env does not change semantics | `test_remote_env_matches_in_process` |
| Scorer is independent of Agent/Env | `test_scorer_reads_trace_only` |
| Privileged information isolation | `test_privileged_state_goes_to_trace_not_agent` |
| Guards cannot be loosened by extra guards | `test_extra_guard_cannot_loosen_mandatory_bounds` |
| The memory layer yields measurable gains and can correct stale memories | `test_spatial_memory_shortens_later_episodes`, `test_stale_memory_is_forgotten` |
| RSI loop + protected scope + rollback | `test_improvement_cycle_promotes_a_validated_candidate`, `examples/rsi_demo.py` |

During implementation the prototype also exposed real problems, which have been fixed: the MJCF default angle unit is degrees, which locked the joints; clipping all position-control targets uniformly to ±2.8 rad prevented joints without limits from reaching targets behind them; the Reasoner misjudged its own observations as "stale long-term memory". These problems show that conformance tests and determinism regression tests are necessities.

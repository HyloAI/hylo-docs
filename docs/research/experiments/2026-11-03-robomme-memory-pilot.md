# RoboMME Memory Pilot

Date: 2026-11-03. This extends the [local memory validation](2026-11-03-benchmark-memory.md)
with an isolated remote GPU setup. Setup, synthetic vision probes and training-split calibration
are **not benchmark success rates**. The frozen executor is SERA's grounded-subgoal pi0.5;
the visual planner and memory are Hylo components, so this is not a reproduction of SERA's
reported Codex-planner results.

After user review, this bundle is classified as a **heuristic diagnostic baseline**, not the
proposed general Hylo memory design. The subsequent local count-and-stop parser/action-guard
candidate was withdrawn before GPU execution. It is preserved under
`runs/memory-20261103/retired-rule-candidate/`. The [revised RFC](../../rfcs/RFC-0009-benchmark-memory.md#memory-architecture)
instead prioritizes model-managed keyframes, multimodal evidence, query-conditioned retrieval
and experience-driven improvement. The frozen `pilot-v1` completed unchanged, so its failures
and successes remain attributable to its archived code. Later local parser hardening changes
malformed-output handling only; the run archive is the authoritative source for v1 results.

## Visual Memory

`VisualReportMemory` records a frozen VLM's interpretations with topic, original claim,
confidence and frame citations in the existing append-only journal. It validates the complete
response before any write and rejects citations absent from the request. Its bounded context
selects early and recent versions of topics, preserves chronological order, and reports omitted
entries. It does not silently replace evidence with a summary
(`harness/packages/hylo-memory/src/hylo/memory/visual.py:1`).

An event's emission confidence is 1 because the model response was observed; **the claim inside
that response remains unverified**, with its own confidence. These reports do not automatically
increment a physical-event counter or certify task completion. Frame indices are a logical
ordering clock here, not physical elapsed seconds. Exact physical event counting still requires
validated visual transition extraction.

The pilot adapter preserves every public reset and rollout frame in lossless archives. The
planner consumes chronological contact sheets, current RGB views and bounded report context;
the frozen executor receives RGB, proprioception, task language and one short grounded command.
An additional `FrameEvidence` store retains observed RGB up to an explicit capacity limit and
retrieves up to 32 evenly spaced demonstration frames and 16 diverse rollout frames. Retrieval
is causal and returns copies. This image heuristic can omit important cues under its budget;
lossless storage does not imply perfect model recall
(`harness/packages/hylo-memory/src/hylo/memory/frames.py:1`).

Grounding uses the current front view and renders normalized coordinates into RoboMME's
`<row, column>` convention. Success, reward, seed, oracle subgoals and hidden simulator state
are excluded from model requests. Evaluator metadata is written separately
(`harness/examples/memory/robomme/run_paired.py:1`).

Malformed model output has at most two repair attempts using the same observations and a
schema error. Repairs and original responses are retained. No simulator action is executed
while repairing a response. The loopback-only vision server uses greedy, inference-only
generation from local weights (`harness/examples/memory/robomme/serve_vision.py:1`).

Calibration exposed two grounding failures: confusing a flat landing marker with a raised
button, and locating the carried object when the command requested a placement destination.
The adapter makes the destination explicit and offers RGB region selection. Hylo's existing
`ColourSegmenter` proposes visible regions; an appearance filter handles explicitly named
colors, colored rings and button-cap candidates. A unique matching region supplies its center;
otherwise the VLM selects a numbered candidate. Depth, simulator segmentation and actor poses
are never supplied. These appearance rules were developed on training-split images and are
specific to simple rendered tabletop scenes, not general instance segmentation
(`harness/examples/memory/robomme/grounding.py:1`;
`harness/packages/hylo-manip/src/hylo/manip/perception.py:189`).

Invalid or absent grounding becomes an explicit abstention. Both conditions share bounded
command continuity: the same semantic command may retain its last grounded executor command
for up to 128 frames during temporary occlusion, with the old evidence frame recorded. An old
coordinate is not labeled as newly observed. Otherwise the command is `remain static`.
Thus “memory off” means no episodic report/keyframe retrieval, not a completely stateless
actuator controller. Composite proposals are reduced to their first manipulation stage;
this formatting/control rule does not certify stage completion.

The optional execution monitor uses only the seven observed Panda joint angles, one finger
position, commanded gripper value and RGB. Forward kinematics reads joint origins and axes
from the public Panda URDF. A stable closing aperture creates a contact hypothesis; an 8 cm
relative TCP lift and a low release near the observed colored destination support one
`motion.pick_place` event. The event retains contact/lift/release frame references. Opening
is debounced for at most eight frames; repeated open frames cannot create repeated events.
These thresholds are training-calibrated heuristics, not the simulator's hidden grasp or
object-height predicate (`harness/examples/memory/robomme/execution.py:1`).

The monitor's confidence value is a heuristic score, not a calibrated probability. Exact
recall counts accepted event records exactly; it cannot make a fallible detector exact about
the physical world. A partial count is a lower bound on retained qualifying records, not a
guarantee about the evaluator's hidden count.

Both conditions receive the same current execution phase and phase checks. Only memory on
retrieves accumulated events as a partial, evidence-linked count. Model-generated reports
cannot increment that count. An accepted press persists for a bounded 64-action horizon in
both conditions, so a single replanning call cannot immediately abandon button contact.
This actuator continuity is not a claim that pressing succeeded. The monitor currently
targets Panda colored-cube pick/place instructions; other objects and robots need separate
validated extractors.

## Paired Protocol

- Calibration uses train episode 0; validation is reserved until the integration is frozen.
- Initial pilot: VideoUnmask, PickHighlight, PickXtimes and PatternLock, two validation episodes
  per task and condition, using the benchmark's metadata seeds. IDs **0 and 3** were selected
  before any validation outcomes: the official metadata labels them easy and hard respectively.
  This is a small stratified panel, not the full 50-episode validation distribution.
- Conditions share frozen weights, greedy planner, action chunk length 16 and maximum 1,300
  executed actions. Policy RNG and episode memory reset between episodes. Condition order
  alternates by episode index.
- Hash complete reset RGB/proprioception streams and instruction; reject paired statistics
  when reset hashes or metadata seeds differ. Retain the Hylo source archive and hashes with
  the protocol, and verify that the live vision server matches the archived server source.
- Both conditions see the same current observation window. Memory on additionally processes
  the reset prefix and retains earlier reports. Consequently planner compute is unequal;
  report this cost rather than describing the comparison as compute-matched.
- Retain original benchmark termination and scoring. Report invalid agent outputs and
  infrastructure failures separately, alongside the total attempted episodes. A tiny pilot
  cannot establish general benchmark superiority or authorize promotion of a reusable skill.

## Evaluation Status

The checkpoint archive and history configuration passed their published SHA-256 checks. The
archive contains a nested original workspace path; a symlink exposes the expected
`symbolic-grounded-subgoal/79999` directory without changing weights. The locked policy
environment additionally required `pytest==8.3.5` because an imported runtime module imports
pytest (`references/memory/SERA/src/openpi/models_pytorch/gemma_pytorch.py:3`).

One complete train-0 calibration run (`calibration-v8`, RGB regions enabled) produced:

| Task | Outcome | Executed actions | Wall seconds |
|---|---|---:|---:|
| PickXtimes | Timeout | 1,300 | 415.72 |
| VideoUnmask | Success | 108 | 53.86 |
| PickHighlight | Success | 203 | 57.85 |
| PatternLock | Success | 83 | 58.88 |

These are training calibration observations, not held-out success rates. The counting failure
motivates a separate proprioception/RGB execution monitor: stable closing-jaw aperture,
relative TCP lift computed from the public URDF, and low-height release near an observed
landing region. Its events remain sensor-supported hypotheses with explicit frame evidence;
it never reads environment success or object poses. The monitor prevents premature pickup to
placement switches, while episodic event recall supplies the accumulated cycle count.

`calibration-v10` recorded two sensor-supported cycles but failed after abandoning a button
press after one action chunk. Adding the shared bounded press-continuity rule produced an
official success in `calibration-v11`: **493 actions, 142.01 seconds**, still train episode 0.
Both attempts are retained. This is a calibration result for a single scene, not an estimate
of counting-task generalization.

The implementation is frozen for `pilot-v1`. Earlier calibration attempts exposed malformed
planner output, alternate Qwen point formats, temporary occlusion and incorrect target
selection. Those attempts are retained as calibration failures; interrupted diagnostics are
explicitly marked and are not completed benchmark episodes. The frozen validation panel has
now completed all 16 attempts, with no invalid or incomplete pairs. All eight paired seeds
and full reset-observation hashes matched.

| Task | Memory off | Memory on |
|---|---:|---:|
| VideoUnmask | 1/2 | 1/2 |
| PickHighlight | 0/2 | 1/2 |
| PickXtimes | 0/2 | 2/2 |
| PatternLock | 0/2 | 0/2 |
| Total | **1/8 (12.5%)** | **4/8 (50.0%)** |

There were three memory wins, zero regressions and five ties. Exact McNemar p-values are
**0.125 one-sided and 0.25 two-sided**. This small, preselected easy/hard panel does not
establish statistical superiority, full-benchmark accuracy or transfer to unseen families.
It measures the combined history/report/event-memory bundle, not the isolated effect of
one component. Training successes were excluded.

Memory off used 4,038 actions and 1,123.07 episode wall seconds; memory on used 3,515 actions
and 1,327.52 seconds. VLM calls were 320 versus 326, with 925.73 versus 1,112.63 server wall
seconds. Input image/context budgets differed. Token counts and isolated executor GPU time
were not recorded. Schema repairs were one versus five; all attempts remained in the score.

The hard VideoUnmask prefix produced no useful color/container binding in its early text
reports, and both conditions failed. Hard PickHighlight showed repeated press/pick switching
and both conditions timed out. Hard PickXtimes proposed an early stop with only one recorded
cycle but eventually succeeded; that proposal illustrates unreliable use of available progress
evidence, not a final failure. Both PatternLock validation episodes failed in both conditions,
despite a successful earlier training calibration. These are trace observations and candidate
failure explanations, not controlled attribution of causes.

The revision therefore prioritizes model-directed memory selection and reading, evaluated
against reference mechanisms, rather than further task-specific rule accumulation. The
retired rule candidate has no GPU performance result.

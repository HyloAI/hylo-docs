# Memory Benchmark Comparison

Research date: 2026-11-03. RoboMME and MIKASA-Robo were read at the commits in `references/MANIFEST.md`; no code from these local reference trees was imported or executed for this static study. RMBench and MEMOBench are **paper-only studies**, with online license declarations checked separately; no source checkout, dataset or weight download was performed for them. Their citations therefore use paper sections/pages and primary URLs, not invented local source paths. All paper/README quantities below are **author-reported**, not reproduced.

\[Implemented\] means a traceable implementation, \[Docs/Interface only\] means a specification or paper claim, \[Unverified\] means an unexecuted implementation or inference, and \[Needs model/hardware\] identifies full evaluation requirements. All cross-suite equivalences and integration priorities are Hylo design judgments.

\[Implemented\]\[Unverified\] RoboMME can return several observation frames from reset/demo playback or a macro action. Dropping all but the last frame can erase the task cue. MIKASA's wrapper produces two-camera RGB and seven-dimensional proprioception; the protocol forbids oracle fields and `task_cue`. Its runner discards reset `info` and calls `policy.forward(obs)`, so Hylo must explicitly preserve permitted language and reset episodic memory. These contracts need different adapters (`references/memory/robomme_benchmark/doc/env_format.md:3`; `references/memory/robomme_benchmark/doc/env_format.md:34`; `references/memory/MIKASA-Robo/docs/source/evaluation_protocol.rst:43`; `references/memory/MIKASA-Robo/docs/source/evaluation_protocol.rst:64`; `references/memory/MIKASA-Robo/mikasa_robo_suite/vla/benchmarking.py:445`).

RoboMME pins Python ≥3.11/Torch 2.9.1 and a ManiSkill fork; MIKASA pins Python <3.12/Torch 2.2.1 and another ManiSkill release. ## Integration Order

The subsequent [performance review](memory-performance-review.md) records current strong
configurations, per-family results and protocol differences. In particular, it separates
the five-task MIKASA comparison from the 90-task inventory, and adaptive RoboMME harness
scores from fixed-library evaluation. The priorities below remain integration choices,
not claims about the latest winning method. The initial four-task RoboMME pilot has now
completed; the [redesigned plan](../../rfcs/RFC-0009-benchmark-memory.md#integrated-plan)
targets a frozen-model system across all families.

1. **Keep `hylo-mj-v0` first for deterministic CPU development.** Implement the planned observation allowlist, evaluator isolation, memory-reset semantics and paired seed protocol there before involving external simulation/model stacks. This follows Hylo's existing acceptance criteria, not an external performance claim (`docs/design/mvp-v0.1.md:21`; `docs/design/mvp-v0.1.md:26`).
2. **Integrate RoboMME first among external memory benchmarks.** Its 16-task scope, explicit train/val/test metadata, list-of-frames observation contract and symbolic-subgoal route make it a useful end-to-end test for a frozen-policy harness. The initial pilot covered VideoUnmask, PickHighlight, PickXtimes and PatternLock, one per memory family. The redesigned evaluation must extend to all 16 tasks, preserve original scoring and separately classify infrastructure errors; the four-task pilot is not a replacement benchmark score (`references/memory/robomme_benchmark/src/robomme/env_record_wrapper/episode_config_resolver.py:17`; `references/memory/robomme_benchmark/doc/env_format.md:34`; `references/memory/robomme_policy_learning/examples/robomme/subgoal_predictor.py:245`).
3. **Add MIKASA VLA Short next, then broader groups.** Its cue-controlled tasks can diagnose a failed RoboMME family; the extra negative/checklist/prospective groups expand coverage. Add explicit reset/language handling and preserve canonical evaluation seeds; create separate development seeds rather than tuning on those evaluation episodes (`references/memory/MIKASA-Robo/mikasa_robo_vla_envs.csv:1`; `references/memory/MIKASA-Robo/mikasa_robo_suite/vla/benchmarking.py:445`; `references/memory/MIKASA-Robo/docs/source/evaluation_protocol.rst:64`).
